# 规则交互案例

本目录用于检验术语和规则表示是否能解释具体结算。当前尚未录入或验证交互案例；不把草拟的预期结果作为官方裁定。

## 案例选择

优先选择初始状态可完整描述、涉及少量规则、具有明确来源定位的场景。第一批候选方向为“受到伤害”与“失去体力”的区别、事件触发窗口、效果替换及优先级；具体技能组合及预期结果待资料核验后确定。

每个案例采用 `CASE-0001` 一类稳定 ID，文件名使用 `0001-short-title.md`。变体需说明与原案例不同的状态或操作。

## 记录模板

```markdown
# CASE-编号：案例名称

- 状态：草拟／资料待核实／待验证／验证通过／存在冲突／无法判定
- 适用规则版本、平台、模式及限制：
- 来源 ID、页面／章节／条款定位：
- 涉及概念或规则 ID：

## 问题

本案例试图区分哪些解释，或验证哪条规则？

## 初始状态

角色与座次、当前回合及阶段、体力、手牌与区域、技能版本、标记及其他相关状态。
未知条件明确列出，不默认为无关。

## 操作序列

按发生顺序列出操作、选择、目标、代价和已知触发条件。

## 原始依据

给出可复核定位；必要短摘录与项目解释分别记录。

## 预期结果及其身份

区分来源明确给出的结论、项目假设和仍待判定的结果。
没有充分依据时写“待核实”，并保留不同解释。

## 推演过程

逐步列出状态变化、事件窗口、适用规则、引用依据和分支条件。

## 验证结果

实际观察或人工／程序复核过程、与预期的差异、复核人和日期。
平台实际行为只作为该平台与版本的证据，不直接外推。

## 失败分类与开放问题

区分资料不足、规则歧义或冲突、模型表达不足、实现错误。
记录需要补充的证据及下一步。
```

只有来源、适用范围、初始状态和推导步骤均可审查，且差异已经说明时，才能标记“验证通过”。无法判定同样是有效研究结果，但须明确原因。来源登记见 [source/index.md](../source/index.md)，术语见 [docs/glossary.md](../docs/glossary.md)。
