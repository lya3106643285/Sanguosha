规则行为统一用事件表达。事件、数值、条件、序列、引用和结算结构共用值空间。已产生的值不可变，实际游戏状态和待执行结构都通过生成新值、更新有效引用演进。持续效果由条件或钩子在规则指定的时机或求值位置参与，属性求值本身不会增加发动机会。解释器处理通用的展开与执行，武将、卡牌和技能的具体语义由规则定义提供。

## 2. 事件的递归组成

~~~text
Event          ::= AtomicEvent | CompositeEvent
CompositeEvent ::= NonEmptySequence<Event>
AtomicEvent    ::= Values × NonEmptySequence<Operation>
~~~

此处序列表示组成关系。事件间的执行顺序、分支和循环由边描述。

| 概念 | V0.3 的设计定义 |
| --- | --- |
| 复合事件 | 组织次一级事件，可携带定义、属性与上下文。解释器到达时展开子事件，具体原子操作由叶节点承载。 |
| 原子事件 | 递归展开的叶节点，持有一组值和非空原子操作序列。持有的值可以引用事件或定义，引用本身不会展开执行。 |
| 原子操作 | 解释器的最小执行动作，如读取、计算、生成新值或更新绑定。操作内部没有规则插入时机。 |

每个事件直接或经有限次递归包含至少一个原子事件。事件的**定义、执行实例、实例版本**分别标识可复用的规则、某一次实际结算和该次结算的结构变化。运行时循环可以在每次到达时产生新的事件实例，而每一步向下查找原子事件都须在有限层内完成。

V0.2 的事件可以直接包含操作，执行位置描述到具体操作。V0.3 把操作集中在原子事件中，执行游标先定位到一次具体的原子事件，必要时再定位其内部的操作。候选边界是整个操作序列期间都不开放规则插入。哪些操作的结果须一起提交、哪些步骤可以留下数据版本，仍需靠多牌同时移动等案例验证。

## 3. 按需展开的递归事件图

一局游戏从根事件开始。初始化确定角色、座次和初始条件，回合组织结构按规则选择下一个回合实例；进入回合后才展开阶段，进入阶段后才展开具体规则行为。同一角色的两次回合拥有不同的执行实例。局面、规则或玩家选择可以决定后来展开的结构。[游戏流程](../source/original_rules/md/flow/game.md)

图 `G = (V, E)` 中，节点集合 `V` 包含复合事件与原子事件。复合事件可处于待展开或已展开状态。边集合 `E` 包含有向的顺序、分支、循环和返回关系。**事件是节点，时机是带有规则语义的边。** 普通连接边可用于串联结构和定位控制流，玩家响应只在规则许可的边开放。局部的顺序仍可表达为链；展开一个复合节点会形成子图，插入或调整结构则产生新的图版本。

| 层面 | 所记录的内容 |
| --- | --- |
| 定义图 | 规则允许的事件组成、时机与候选路径 |
| 运行时图 | 本局已展开的实例、已插入的结算及待执行结构 |
| 执行轨迹 | 本局实际经过的事件与边、执行结果及关联的数据版本 |

一个节点可以留在待执行结构中却因分支而从未发生。只有执行轨迹能回答该节点是否实际经过。图的节点、边和轨迹均可用统一值空间表达。由解释器直接展开、用显式原子事件展开、借助 `Insert` 生成下一级结构，都是候选表达。

## 4. 时机、插入和跳转

时机对应一次规则规定的边界。把时机建模为边，可以用同一位置描述允许插入什么、控制流可跳到哪里、规则事实属于哪个时间点。规则原文定义的是结算中的瞬间，图中的边是本项目对它的表达。挂在边上的条件或待插入事件的条件负责限制合法性，条件如何组织仍待确定。[事件与时机](../source/original_rules/md/glossary/event.md)

**时机定义**可复用，例如“受到伤害后”。**时机实例**属于一次实际结算，需要能够定位其所属的事件实例、目标结算人次、边及本次经过。同一事件可能对同一角色结算两次，同名边在这两次结算中分别产生时机实例。一个既有时机在子结算返回后恢复，仍用原来的实例和已处理记录。

| 控制流操作 | 语义 | 本版边界 |
| --- | --- | --- |
| `Insert(Event, Position)` | 改变待执行结构，在当前位置加入合法的插入结算，或为未来位置追加事件 | 活跃的插入立即优先结算。为未来位置加入的事件要到实际进入时才发生。插入位置的寻址仍待确定。 |
| `Jump(TimingReference)` | 改变接下来执行的路径，目标可为可定位的时机或普通连接位置 | 可表达分支、跳过、提前结束、循环及进入或返回插入事件。默认顺序可以直接推进。 |

例如，插入结算先用 `Insert` 表达结构变化，再用 `Jump` 表达控制权转移。两者是规则表达层的基础操作，底层可共用值的创建和绑定更新。原子操作内部没有规则时机；如从操作序列发出控制流请求，何时实际切换至目标位置属于待验证的执行语义。

### 暂停、恢复与终止

进入合法时机可开放它。若有事件插入，父时机暂时关闭，父流程保留该时机实例、目标人次、已经处理的发动机会及原来的继续位置。子事件完成后，规则若允许继续处理该时机，便以最新真实状态恢复同一实例。离开后已按规则彻底结束的时机只能从历史读取。开放和关闭是控制流状态，是否显式记录、是否用独立的 `Open` 和 `Close` 表达仍是候选问题。[插入结算顺序原则](../source/original_rules/md/rule/principle.md)

以可以在受到伤害后选择摸牌的【奸雄】为例。解释器在当前“受到伤害后”保存时机与进度，进入插入的技能结算，再按需展开其中的摸牌事件。技能结算结束后回到原来的“受到伤害后”。摸到的牌仍在当前状态里，已经消费的发动机会仍有记录，后续资格依条款检查。多名角色同一时机通常从当前回合角色开始按逆时针座次依次处理；单角色顺序、特殊起点及条件复查沿用相应条款。规则顺序已有依据，仍待确定的是它如何作用于动态展开的后继和返回位置。[【奸雄】牌文](../source/original_rules/md/card/hero/wei.md) · [多角色及单角色结算顺序](../source/original_rules/md/rule/principle.md)

濒死提供了另一个结果。轮到某角色救援，其用牌或技能令濒死角色回复过体力却仍未达到 1 时，先前的“处于濒死状态时”结束，规则开启一个新的同名时机，从刚处理的角色开始继续。原来绑定在整次濒死结算上的限制仍有效。模型应能分别表达返回同一实例、结束旧实例后开启新实例，以及沿用上层事件的限制。[濒死流程](../source/original_rules/md/flow/neardeath.md)

## 5. 规则时间与数据版本

规则层通过事件实例及其时机定位问题，例如哪一次“指定目标后”或哪一次“受到伤害后”。**快照（Snapshot）**记录某个逻辑边界上的不可变数据版本，包括适用的状态、有效引用，也可关联执行位置和结构版本。时机实例可以关联多个快照。

| 手工推演边界 | 时机实例 | 真实数据版本 | 玩家手牌数 |
| --- | --- | --- | ---: |
| 伤害结算开放“受到伤害后” | T1，初次开放 | S0 | 2 |
| 合法插入一个摸两张牌的示意事件 | T1，暂停 | S1 | 2 |
| 子事件完成 | 子事件完成边界，T1 仍处于暂停 | S2 | 4 |
| 继续原伤害结算 | T1，恢复 | S3 | 4 |

S0 至 S3 仅用于展示可记录的边界，手牌相同的边界可以共享数据。返回 T1 后，读“现在有几张手牌”应得到 4；读“首次到达 T1 时有几张”应得到 2。事件挂起前确定的属性继续使用已确定的值。能否重算、应读哪个边界、何时解析动态引用，均由具体规则决定。

| 求值意图 | 读值方式 |
| --- | --- |
| 读取已确定的牌面 | 取本次虚拟牌构造时的确定值。材料日后移区时仍沿用该值。 |
| 检查实体牌是否仍在处理区 | 以实体身份查效果执行时的当前真实版本。 |
| 解释当时为何允许某项选择 | 沿轨迹定位当时的时机、版本及已记录的求值结果。 |
| 检测牌的使用是否合法 | 可按规则派生假设快照。例如最后一张手牌【火攻】先按已在处理区计算。该视图仅供查询，真实移动及其时机由实际执行产生。 |

“视为”涉及的内容须按条款处理。假设移区是合法性查询的数据视图，视为已使用或响应成功可以产生规则事实，视为使用一张牌可涉及构造虚拟牌。实际状态变化仍由执行产生。[虚拟牌专题](../source/original_rules/md/flow/virtual.md) · [合法性检测专题](../source/original_rules/md/flow/condition.md) · [打出流程](../source/original_rules/md/flow/play.md) · [游戏牌与“视为”](../source/original_rules/md/glossary/gamecard.md)

## 6. 解释器候选推进方式

1. 从逻辑控制位置解析要进入的事件实例，按需展开复合节点，直至找到可执行的原子事件。
2. 以具体原子事件实例为执行游标的落点，依序执行其中的操作并记录实际结果。若有规则允许的控制流变化，在相应边界处理。
3. 沿默认后继或显式跳转到达连接边。遇到规则时机，处理合法的插入和相应的父流程暂停，再依规则恢复、终止或继续。
4. 子图完成时返回其调用处，持续按上述规则推进，直至根事件结束。

原子事件的实际执行位置与边上的逻辑控制位置都可由一个游标表达。跳到待展开节点时如何解析目标、图版本切换后如何定位恢复点、跨层跳转须经过哪些收尾，尚未形式化。

## 7. 对照 V0.2 的规则案例

**牌文核对。** V0.2 的早期任务书把直接响应【杀】写成打出【闪】，仓库中的 V0.2 第 4 节已更正。目标角色在此次【杀】生效前**使用【闪】**，按用牌结算，其效果抵消该目标的此次结算。【万箭齐发】的效果要求目标打出【闪】，这才适用声明打出的牌名即视为响应成功的流程。【护驾】还可让其他角色打出【闪】参与嵌套响应，主公自己的外层流程仍按其声明区分使用或打出。[基本牌【闪】](../source/original_rules/md/card/basic.md) · [使用流程](../source/original_rules/md/flow/use.md) · [打出流程](../source/original_rules/md/flow/play.md) · [【万箭齐发】](../source/original_rules/md/card/scroll.md) · [【护驾】](../source/original_rules/md/card/hero/wei.md)

| 规则分支 | 候选控制流 | 轨迹应保留的内容 |
| --- | --- | --- |
| 【杀】被【闪】抵消 | 处理此次被抵消时的合法机会，再根据结算结果选路。抵消维持时跳过该目标人次的“生效时”和“生效后”，继续其余人次或整张牌的收尾。 | 两次用牌及响应关系、该目标人次的抵消。适用时先结算【贯石斧】等技能，【贯石斧】成功后此【杀】仍可生效。 |
| 全部伤害被防止 | 防止效果结算完毕后到“伤害结算结束时”，越过扣减体力及“造成伤害后”“受到伤害后”。 | 已进入伤害结算、已执行的防止效果、该次伤害未造成或受到的判定，以及伤害结算结束时及其适用的后续处理。 |
| 取消目标或牌对目标无效 | 按条款结束受影响的目标流程。使用结算前目标因插入减为零时，插入结束后终止整张牌的使用流程并按条款清理。对目标无效时终止对该目标的结算，继续其余目标。 | 已有的用牌事实、目标变化、已发生的子事件及仍需执行的收尾。 |
| 【乐不思蜀】令角色跳过出牌阶段 | 判定为非红桃时记录跳过效果。待相应阶段应进入时选择绕过其流程。 | 判定、牌效果及其结算结束后的清理仍发生，被跳过的阶段没有产生其阶段开始时的结算事实。 |

上表把分支写成对后续路径的选择。未访问的节点可保留在定义或待执行结构中，轨迹只记实际经过的节点和边。用牌、抵消、伤害结算开始、实际造成伤害是不同作用范围的事实，应通过历史记录分别查询。[使用流程](../source/original_rules/md/flow/use.md) · [抵消、无效与取消](../source/original_rules/md/glossary/event.md) · [装备技能【贯石斧】](../source/original_rules/md/card/equipment.md) · [伤害流程](../source/original_rules/md/flow/damage.md) · [【乐不思蜀】](../source/original_rules/md/card/scroll.md)

## 8. 未决问题与下一轮验证

| 范围 | 未决问题 | 可用于核对的案例 |
| --- | --- | --- |
| 展开与组成 | 复合事件精确的展开语义、属性与子事件如何关联、原子事件最小划分、定义与实例及版本的引用关系 | 按需进入下一回合、同一角色重复结算 |
| 控制流与寻址 | 节点和边的稳定地址、跳转目标尚未展开、跨层作用域、图版本变化后的恢复、同边循环中新实例与返回旧实例的区分 | 【流离】后的双重目标人次、插入技能后的返回、濒死重复响应 |
| 时机与顺序 | 临时关闭与终止的判定、时机是否需要独立状态、同一时机如何将既定座次和单角色选择映射到按需定位与资格复查 | 【甘露】、【慷忾】、当前回合角色死亡后的未完成结算 |
| 数据与原子边界 | 时机和数据版本的关联、固定版本引用与动态身份引用、属性重算和锁定、假设快照适用范围、原子事件的提交边界 | 多牌同时移动、【章武②】改变去向、最后一张【火攻】 |
| 规则与轨迹 | 多目标独立结算、伤害转移与防止、连环传导、扣减体力与濒死嵌套返回 | 【天香】与【铁索连环】的组合、转移后防止伤害、濒死中插入死亡结算 |

下一轮验证应给出可供推导的事件定义、合法边、起始状态和玩家选择，再逐项比对得到的轨迹与规则预期。本版的图、游标及控制流操作均为语义设计，具体结构与执行机制待这些案例约束。
